    In Primitive DS - we can only save single values
    In Non-primitive DS - we can save multiple values

    In DSA, We use Non-Primitive DS to make our application faster

    Collection framework is a part of Non-Primitive DS (List, Queue, Set, Map)

    We have arrays to store multiple elements ,so what is need of collection framework then
    Array -
        1. Arrays can store primitive(int, char, float) and non-primitive DS(objects)
        2. Arrays can store only same type of data
        3. Arrays are fixed, we can't increase or decrease the size of an array at runtime
        4. In Arrays, we have to develop own techniques for searching or sorting , etc
    Collection Framework -
        1. Collection Framework can store non-primitive DS(objects) (means everytime we add even an integer it will add as an object in it)
        2. CF can store different or heterogeneous type of data
        3. CF are not fixed, we can increase or decrease the size of an array at runtime
        4. CF provides an API, which provides interface, classes and method

Collection FrameWork and Lists :
    Implementation of multiple types of Data Structure is given by Java. So we don't have to create them manually.

    Q.What is collection?
    ans. collection is a simply object that represent a group of objects

    Q.What is collection Framework?
    ans. In Collection Framework there are interfaces and classes to manage collections

    Collection Framework has 2 main parts -
        1. java.util.Collection (We can directly store data)
        2. java.util.Map (We can store data using key,value)

    We can apply loops on collection interface as it implements Iterable interface

Java Collection Framework :
    Java Collection Framework provides a set of interfaces and classes to implement various data structures and algorithms.
    These include several methods to perform different operations on collections.

A. Iterable(I) :
    Collection(I) :
        a. List(I) :
            1. ArrayList(C) : A resizable array implementation of List with fast random access.
                              | Operation   | Time               |
                              | ----------- | ------------------ |
                              | get(index)  | **O(1)**           |
                              | add(end)    | **O(1)** amortized |
                              | add(middle) | **O(n)**           |
                              | remove      | **O(n)**           |
                              | search      | **O(n)**           |

            2. LinkedList(C) : A doubly linked list implementation that allows fast insertions and deletions.
                               | Operation              | Time     |
                               | ---------------------- | -------- |
                               | get(index)             | **O(n)** |
                               | add/remove (head/tail) | **O(1)** |
                               | add/remove (middle)    | **O(n)** |
                               | search                 | **O(n)** |

            3. Vector(LC) : A synchronized legacy List implementation similar to ArrayList.
                            | Operation     | Time                |
                            | ------------- | ------------------- |
                            | get           | **O(1)**            |
                            | add/remove    | **O(n)**            |
                            | thread-safety | Synchronized (slow) |

                3.1 Stack(C) : A legacy LIFO (Last In First Out) stack implementation extending Vector.
                               | Operation | Time     |
                               | --------- | -------- |
                               | push      | **O(1)** |
                               | pop       | **O(1)** |
                               | peek      | **O(1)** |

            4. CopyOnWriteArrayList(C) : A thread-safe List where modifications create a new copy of the underlying array.
                                         | Operation  | Time               |
                                         | ---------- | ------------------ |
                                         | get        | **O(1)**           |
                                         | add/remove | **O(n)**           |
                                         | iteration  | **O(n)** (no lock) |

        b. Set(I) :
            1. HashSet(C) : An unordered Set implementation backed by a hash table.
                            | Operation | Time     |
                            | --------- | -------- |
                            | add       | **O(1)** |
                            | remove    | **O(1)** |
                            | contains  | **O(1)** |

            2. LinkedHashSet(C) : A HashSet that maintains insertion order of elements.
                                  | Operation | Time            |
                                  | --------- | --------------- |
                                  | add       | **O(1)**        |
                                  | remove    | **O(1)**        |
                                  | contains  | **O(1)**        |
                                  | order     | Insertion order |

            3. TreeSet(C) : A sorted Set implementation that orders elements using natural order or comparator.
                            | Operation | Time         |
                            | --------- | ------------ |
                            | add       | **O(log n)** |
                            | remove    | **O(log n)** |
                            | contains  | **O(log n)** |

            4. EnumSet(C) : A high-performance Set implementation designed specifically for enum types.
                            | Operation | Time     |
                            | --------- | -------- |
                            | add       | **O(1)** |
                            | remove    | **O(1)** |
                            | contains  | **O(1)** |

            5. ConcurrentSkipListSet(C) : A thread-safe, sorted Set implementation based on a skip list.
                                          | Operation | Time         |
                                          | --------- | ------------ |
                                          | add       | **O(log n)** |
                                          | remove    | **O(log n)** |
                                          | contains  | **O(log n)** |

            6. CopyOnWriteArraySet(C) : A thread-safe Set backed by a CopyOnWriteArrayList.
                                        | Operation  | Time                   |
                                        | ---------- | ---------------------- |
                                        | add/remove | **O(n)**               |
                                        | contains   | **O(n)**               |
                                        | iteration  | **O(n)** (thread-safe) |

            7. ImmutableSet(C) : An unmodifiable Set whose contents cannot be changed after creation.
                                 | Operation    | Time          |
                                 | ------------ | ------------- |
                                 | read         | **O(1)**      |
                                 | modification |  Not allowed  |

        c. Queue(I) :
            1. LinkedList(C) : A doubly linked list that can act as both a List and a Queue.

            2. Deque(I) :
                2.1. ArrayDeque(C) : A resizable array-based implementation of Deque with no capacity restrictions.
                                     | Operation              | Time     |
                                     | ---------------------- | -------- |
                                     | add/remove (head/tail) | **O(1)** |
                                     | search                 | **O(n)** |

                2.2. LinkedList(C) : This operation like to remove in middle is more efficient in LLD instead of ArrayDeque
                                     | Operation  | Time     |
                                     | ---------- | -------- |
                                     | add/remove | **O(1)** |
                                     | contains   | **O(n)** |

                2.3. ConcurrentLinkedDeque(C) : A thread-safe, non-blocking Deque implementation.
                                                | Operation  | Time     |
                                                | ---------- | -------- |
                                                | add/remove | **O(1)** |
                                                | contains   | **O(n)** |

            3. PriorityQueue(C) : A queue where elements are processed based on priority rather than insertion order.
                                  | Operation | Time         |
                                  | --------- | ------------ |
                                  | add       | **O(log n)** |
                                  | poll      | **O(log n)** |
                                  | peek      | **O(1)**     |

            4. BlockingQueue(I) : put/take -> O(1) or O(log n)
                4.1. ArrayBlockingQueue(C) : A bounded, thread-safe blocking queue backed by an array.
                                             | Operation | Time     |
                                             | --------- | -------- |
                                             | put/take  | **O(1)** |

                4.2. LinkedBlockingQueue(C) : A optionally bounded, thread-safe blocking queue backed by linked nodes.
                                              | Operation | Time     |
                                              | --------- | -------- |
                                              | put/take  | **O(1)** |

                4.3. PriorityBlockingQueue(C) : A thread-safe blocking queue that orders elements by priority.
                                                | Operation | Time         |
                                                | --------- | ------------ |
                                                | put/take  | **O(log n)** |

                4.4. SynchronousQueue(C) : A blocking queue with no storage that directly hands off elements between threads.
                                           | Operation | Time               |
                                           | --------- | ------------------ |
                                           | put/take  | **O(1)** (handoff) |

                4.5. DelayQueue(C) : A blocking queue where elements become available only after a delay expires.
                                     | Operation | Time         |
                                     | --------- | ------------ |
                                     | add       | **O(log n)** |
                                     | take      | **O(log n)** |

            5. ConcurrentLinkedQueue(C) : A thread-safe, non-blocking FIFO queue implementation.
                                          | Operation  | Time     |
                                          | ---------- | -------- |
                                          | add/remove | **O(1)** |
                                          | contains   | **O(n)** |

            6. ConcurrentLinkedDeque(C) : Everything is same as ConcurrentLinkedQueue, just can add or remove from both ends of queue
                                          | Operation  | Time     |
                                          | ---------- | -------- |
                                          | add/remove | **O(1)** |
                                          | contains   | **O(n)** |

B. Map(I) :
    1. HashMap(C) : An unordered Map implementation offering fast key-value access.
                    | Operation | Time     |
                    | --------- | -------- |
                    | put       | **O(1)** |
                    | get       | **O(1)** |
                    | remove    | **O(1)** |

        1.1. LinkedHashmap(C) : A HashMap that maintains insertion or access order.
                                | Operation      | Time               |
                                | -------------- | ------------------ |
                                | put/get/remove | **O(1)**           |
                                | order          | insertion / access |

        1.2. WeakHashMap(C) : A Map where entries are removed when keys are no longer strongly referenced.
                              | Operation | Time         |
                              | --------- | ------------ |
                              | put/get   | **O(1)**     |
                              | cleanup   | GC dependent |

        1.3. IdentityHashMap(C) : A Map that compares keys using reference equality (==) instead of equals().
                                  | Operation | Time     |
                                  | --------- | -------- |
                                  | put/get   | **O(1)** |

    2. HashTable(LC) : A legacy synchronized Map implementation.
                       | Operation   | Time                |
                       | ----------- | ------------------- |
                       | put/get     | **O(1)**            |
                       | performance | slow (synchronized) |

    3. SortedMap(I) : A Map that maintains keys in sorted order.
        3.1. NavigableMap(I) : A SortedMap with navigation methods to locate the closest matches.
            3.1.1. TreeMap(C) : A red-black tree based Map that keeps keys sorted implements SortedMap and NavigableMap.
                                | Operation | Time         |
                                | --------- | ------------ |
                                | put       | **O(log n)** |
                                | get       | **O(log n)** |
                                | remove    | **O(log n)** |

    4. ConcurrentMap(I) : A Map designed for safe concurrent access by multiple threads.
        4.1. ConcurrentHashmap(C) : A high-performance, thread-safe Map that avoids full synchronization.
                                    | Operation      | Time             |
                                    | -------------- | ---------------- |
                                    | put/get/remove | **O(1)**         |
                                    | thread-safety  | high performance |

        4.2. ConcurrentSkipListMap(C) : A thread-safe, sorted Map implementation based on a skip list.
                                        | Operation | Time         |
                                        | --------- | ------------ |
                                        | put       | **O(log n)** |
                                        | get       | **O(log n)** |
                                        | remove    | **O(log n)** |

    5. EnumMap(C) : A Map implementation optimized for enum keys.
                    | Operation | Time     |
                    | --------- | -------- |
                    | put/get   | **O(1)** |

    6. ImmutableMap(C) : An unmodifiable Map whose entries cannot be changed after creation.
                         | Operation    | Time          |
                         | ------------ | ------------- |
                         | read         | **O(1)**      |
                         | modification | Not allowed   |





Ultra-short revision tip
    List → order matters
    Set → uniqueness matters
    Queue → processing order matters
    Map → key-value lookup
    Concurrent → thread safety
    CopyOnWrite → thread safety works on separate copy and then reflect on original copy during execution so thread does not get interrupted
    Immutable → no modification allowed


Most Useful Collections for DSA
    ArrayList – A dynamic array that allows fast indexed access.
    HashSet – A collection that stores unique elements with fast lookup.
    TreeSet – A set that stores unique elements in sorted order.
    ArrayDeque – A double-ended queue used as both stack and queue.
    PriorityQueue – A queue that always processes the highest-priority element first.
    HashMap – A key-value store with fast average-time lookup.
    TreeMap – A map that keeps keys sorted at all times.
